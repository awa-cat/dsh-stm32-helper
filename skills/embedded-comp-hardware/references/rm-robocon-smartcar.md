# RM / RoboCon / 智能车 硬件与电控架构对照

> 条目为**通用工程模式**；具体允许的 MCU、功率、传感器、车模以**当年官方规则**为准。  
> RM 官方资料入口（已核实存在）：https://bbs.robomaster.com/wiki/20204847  

## 1. 三类赛事对比

| 维度 | 全国大学生智能车竞赛 | RoboMaster（RMUC 等） | RoboCon（全国大学生机器人大赛） |
|---|---|---|---|
| 核心比什么 | 赛道速度/完成度/稳定性 | 场地对抗、攻击与基地血量 | 当年主题任务（抓取/搬运/投掷/协作） |
| 典型机器人 | 单车，缩微赛道 | 多车：步兵/英雄/工程/哨兵等 | 1–2 台专用机器人 |
| 动力 | 有刷为主，部分无刷 | 大功率无刷+CAN 电调生态 | 混合：电机+气动常见 |
| 感知 | 电磁/摄像头/编码器/IMU | 视觉+IMU+裁判系统+遥控 | 光电/编码器/限位/简单视觉 |
| 算力 | MCU 为主（F1/TC/RT/STC/MSPM0…） | MCU + Linux 视觉板 | 多为 MCU，任务简单则全 MCU |
| 通信 | 调试串口/无线调参 | CAN 总线+遥控+裁判系统串口协议 | 串口/无线/硬线逻辑 |
| 电源 | 小容量锂电+BEC | 高功率电池+电源管理（规则约束） | 电池+电磁阀耗气耗电 |
| 软件重点 | PID 巡线、元素、调参 | 底盘解算、云台、发射、导航、角色策略 | 状态机、顺序动作、精度定位 |
| 文档 | 教程/车队笔记/逐飞库 | **官方规则手册+制作规范+协议** | 组委会当年规则与场地说明 |

## 2. RoboMaster 电控架构（常见）

```
遥控接收 ──► 主控 MCU ──CAN──► 底盘电机电调（麦克纳姆/舵轮）
                │  ├──CAN──► 云台/发射机构电机
                │  ├──UART──► 裁判系统机载模块（电量/血量/功率等）
                │  └──UART/网口──► 视觉算力板（自瞄/识别）
                └──► 蜂鸣器/灯带/超级电容管理
```

硬件要点：

| 模块 | 知识点 |
|---|---|
| 底盘 | 麦克纳姆运动学：vx, vy, ω → 四轮转速；轮组安装方向约定 |
| 云台 | IMU 角度闭环 + 电机速度环；机械回差与标定 |
| 发射 | 摩擦轮/拨弹电机；热量与弹道约束见规则 |
| 裁判系统 | 官方机载端 + **串口协议**（wiki 资料中心）；功率/血量逻辑勿乱改 |
| 功率 | 按规则设计电源与超级电容；软件限功率保护 |
| 多机 | 场上角色不同，固件可配置；失联保护必须停火停车 |

麦克纳姆逆解（示意，轮向符号按机械定义改）：

```c
void Mecanum(float vx, float vy, float omega, float *w)
{
    // w[0..3] 四个轮目标速度
    w[0] = vx + vy + omega;
    w[1] = vx - vy + omega;
    w[2] = vx - vy - omega;
    w[3] = vx + vy - omega;
}
```

## 3. 智能车电控架构（与培训教程衔接）

```
电感/摄像头/编码器/IMU
    → 特征 error / element
    → 转向 + 速度策略
    → 差速电机 PWM（+ 舵机）
    → 屏幕/串口调参
```

硬件要点见 `smartcar-stm32`；开源库见逐飞 TC264/RT1064/MSPM0/STC 等。

## 4. RoboCon 硬件模式（按年题变化）

常见机电组合：

| 子系统 | 硬件 | 软件 |
|---|---|---|
| 移动底盘 | 有刷/无刷差速或全向 | 编码器航迹 + 寻线/定位 |
| 升降/伸缩 | 直流电机+限位 或 气缸 | 状态机+到位检测 |
| 夹取 | 舵机/电机+气动夹爪 | 开合到位、力/电流保护 |
| 投掷/击打 | 凸轮、弹射、电磁 | 触发时序、位置重复精度 |
| 识别 | 颜色/二维码/简单视觉 | 分拣逻辑 |
| 气动 | 气泵、电磁阀、气缸 | 电磁阀 GPIO、延时与顺序 |

RoboCon 纪律：

- **动作顺序表**先写清楚再写代码（每一步传感器条件与超时）
- 机械重复定位精度往往决定成绩，软件只补偿可补偿部分
- 场地边缘/裁判区逻辑硬编码要对照当年规则图

## 7. Agent 生成代码时的硬件假设模板

```c
/* board_assumptions.h — 生成前由用户确认或改为 TODO */
#define ASSUMED_MCU           "STM32F103C8T6"  /* 或 TC264/RT1064/RM C板 */
#define ASSUMED_BUS           "UART"           /* 或 CAN */
#define ASSUMED_DRIVE         "DIFF_2WD"       /* 或 MECANUM4 / ACKERMANN */
#define ASSUMED_HAS_IMU       0
#define ASSUMED_HAS_ENCODER   1
#define ASSUMED_RULES_VERIFIED 0 /* 0=未对照当年规则，输出中必须提示 */
```

`ASSUMED_RULES_VERIFIED==0` 时，回复里必须含「未对照当年规则，参数与器件可能违规/不匹配」。
